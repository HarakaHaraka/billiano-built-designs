# Billiano Built Designs

**Sustainable Building Services & Energy Design**

This repository is the **single source of truth** for the Billiano Built Designs
website and admin system. Everything flows one way:

> **edit → commit → push to `main` → automatic deploy.**

No more drag-and-drop deploys. If it isn't in this repo, it isn't on the site.

- **Public site (frontend):** static single-page app, deployed on **Netlify** →
  <https://billianobuiltdesigns.co.uk>
- **Admin system (backend):** password-protected Express + SQLite app, deployed on
  **Render**, completely separate from the public site.

Build briefs: `BILLIANO-REBUILD.md` + `BILLIANO-REBUILD-ADDENDUM.md` (addendum wins
where they conflict).

## The golden rule — how changes go live

Every change to the website is made by editing a file in this repository and saving it
back to the `main` branch. The moment that happens, Netlify rebuilds and publishes the
site automatically — usually within a minute or two. There is **nothing else to do**: no
uploading, no drag-and-drop, no "publish" button.

If you use GitHub in the browser:

1. Open the file you want to change on <https://github.com/HarakaHaraka/billiano-built-designs>.
2. Click the **pencil (Edit)** icon (or **Add file → Upload files** for photos).
3. Make your change.
4. Scroll down, write a short note of what you changed, and click **Commit changes**
   (commit straight to `main`).
5. Wait ~1–2 minutes — the live site updates itself.

## Owner how-to (no coding required)

### Add the hero background photos

The home page has a full-screen hero that slowly crossfades between photographs
(heat pump installs, solar arrays, daylight architecture). Until photos are supplied it
shows a brand-green gradient. To switch the photos on:

1. **Upload the image files** to `frontend/public/assets/legacy/` (GitHub →
   **Add file → Upload files**). Recommended: JPG, ~1920px wide, under ~400KB each.
   Suggested names are already staged: `hero-solar-roof.jpg`, `hero-heat-pumps.jpg`,
   `hero-solar-terrace.jpg`, `hero-atrium.jpg`.
2. **Edit `frontend/public/data/hero.json`** and move each entry from the `_staged`
   list into the `images` list (they are pre-written to match the four filenames above).
   Only list files that actually exist, or the page would request missing images.
3. Commit. The hero starts rotating automatically — every 6 seconds with a slow
   crossfade, static for visitors who have "reduce motion" switched on.

### Add a portfolio project

Edit **`frontend/public/data/projects.json`**. Each project is one block like this:

```json
{
  "id": "riverside-heat-pump",
  "title": "Riverside cottage — air-source heat pump",
  "workType": "Heat pump design",
  "outcome": "Designed a low-temperature ASHP system; installed and commissioned.",
  "photo": "/data/photos/riverside.jpg"
}
```

- Put project photos in `frontend/public/data/photos/` and reference them as
  `/data/photos/yourfile.jpg`; leave `"photo": ""` if you have none yet.
- Do **not** include `"placeholder": true` on a real project — that flag marks the three
  sample cards. Delete the samples once real work is added.

### Update the accreditation register

The register is colour-coded and filterable: **green = Attained · amber = In progress ·
grey = Planned · Partner-held**. Its entries live in **`frontend/public/assets/app.js`**
in the `REGISTER` list near the top — one line per credential:

```js
{ status: 'attained', name: 'BEng (Hons) Mechanical Engineering', note: 'Verified qualification' },
```

- `status` is one of `attained`, `progress`, `planned`, `partner`.
- To move a credential between statuses, just change its `status` value.
- To add one, copy a line and edit it. To replace a placeholder, swap the `ph('…')`
  call for the real name in quotes.
- **Honesty rule: nothing may show `attained` unless genuinely awarded.**
- When ICO registration confirms, also update the two other spots where it appears:
  the home-page credentials card and the "Company & registration" block (search
  `ICO registration` / `status-progress` in the same file).

### Edit the legal documents (Terms / Privacy / Complaints)

The Terms of Service, Privacy Notice and Complaints Procedure pages render directly
from markdown files — edit the text, never the layout:

- `frontend/public/content/docs/terms-of-service.md`
- `frontend/public/content/docs/privacy-notice.md` ← still a placeholder awaiting your text
- `frontend/public/content/docs/complaints-procedure.md`

Anything written as `[PLACEHOLDER: …]` shows on the site as a flagged marker until you
replace it. Plain markdown: `#` headings, `**bold**`, `-` bullet lists.

### Fill in the company number & insurance details

- **Company number** — site footer (`frontend/public/index.html`) and the
  accreditations page (`frontend/public/assets/app.js`); search `company number` in both.
  Also in `content/docs/terms-of-service.md`.
- **Insurance table** — in `app.js`, the three `insuranceRow(...)` lines use `tc()`
  ("to confirm") cells; replace with real insurer / policy number / cover once purchased.

## The enquiry form — turning on email notifications

The "Get a quote / make an enquiry" panel (header button, footer button, and the
floating **Enquire** bubble) submits a structured form — name, type of service, nature
of the project, email, phone, message — through **Netlify Forms**. Submissions are
stored in Netlify and must be wired to email once, by hand:

1. Netlify → your site → **Forms** — check form detection is **enabled** (Netlify may
   prompt "Enable form detection"; click it, then redeploy once).
2. **Forms → Form notifications → Add notification → Email notification.**
3. Choose form **`enquiry`**, recipient `enquiries@billianobuiltdesigns.co.uk`. Save.
4. **Repeat step 2–3** with recipient `Executive@billianobuiltdesigns.co.uk` — both
   inboxes then receive every submission (addendum requirement).

The panel also offers direct routes: both email addresses, phone (07849 549740) and
WhatsApp (07943 569024 — also the floating WhatsApp bubble, `wa.me/447943569024`).

## Frontend — run & build locally

Requires Node 18+.

```bash
cd frontend
npm install
npm run build      # compiles Tailwind into public/assets/app.css
npx serve public   # or: python3 -m http.server -d public 8080
```

`npm run watch` rebuilds the CSS automatically while you edit. The site is a
single-page app — deep links work because Netlify serves `index.html` for any unknown
path (configured in `netlify.toml`).

## Admin backend — run locally & deploy

The admin system is a separate Express app in `backend/`. It is **password-protected**,
stores data in **SQLite**, and has two kinds of user:

- **Owner** — full access: projects, financials (cost, quote, commission, margin),
  professionals, expenditures, receipts, and user management.
- **Limited** — a professional who can log in and add **only their own** inventory costs,
  labour and receipts on the projects they are **assigned to**. They can never see other
  professionals' figures, company margins, or commission. Enforced on the server.

### Run it locally

```bash
cd backend
npm install
cp .env.example .env          # then edit .env — set a SESSION_SECRET and OWNER_* values
npm run seed                  # creates the first owner account from OWNER_* in .env
npm start                     # http://localhost:4000  → /login
```

All environment variables are documented in **`backend/.env.example`**.
**Never commit a real `.env`.**

## Deploy pipeline

### Netlify (frontend)

`netlify.toml` pins: base `frontend`, build `npm run build`, publish `frontend/public`,
production branch `main`.

1. Netlify → **Add new site → Import an existing project → Deploy with GitHub →**
   `HarakaHaraka/billiano-built-designs` → production branch **`main`** → **Deploy**.
2. Then set up form notifications (see above).

### Moving the domain off the old drag-and-drop site

1. Netlify → open the **old** site → **Site configuration → Domain management →
   Custom domains →** `billianobuiltdesigns.co.uk` → **Options (⋯) → Remove domain**.
2. Open the **new** (repo-connected) site → **Domain management → Add a domain →**
   `billianobuiltdesigns.co.uk` → **Verify → Add** (add `www` too if used).
3. HTTPS re-provisions automatically (**Domain management → HTTPS** if it stalls).
4. Delete the old drag-and-drop site so it can never be published again.

> This is what finally removes the old red-banner script error
> (`/_ds/organic-*`) for visitors — this repo contains no such reference.

### Render (backend)

1. Render → **New → Blueprint** → connect this repo; `render.yaml` creates the service
   (root `backend`, persistent 1 GB disk at `/var/data` — requires a paid plan).
2. Set `OWNER_USERNAME`, `OWNER_EMAIL`, `OWNER_PASSWORD` when prompted.
3. After first deploy: service **Shell** → `npm run seed` → log in at `/login`.
